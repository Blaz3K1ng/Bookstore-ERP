# PageCraft Bookstore ERP — Microservices Architecture

> Mini ERP system for an online bookstore, built with Laravel microservices.

---

## Architecture Overview

```
Client / Frontend
       │
       ▼
┌─────────────────────────┐
│    API Gateway :8000    │  ← Single entry point (Laravel + Guzzle proxy)
│  AuthenticateGateway    │  ← JWT validated here before forwarding
└─────────┬───────────────┘
          │  (routes per resource)
    ┌─────┼──────────────────────────────────────┐
    ▼     ▼           ▼           ▼              ▼
 Auth   Inventory  Order       Customer       Finance
:8001   :8002      :8003       :8004          :8005
  │       │          │    │        │              │
  │       │      REST│ RabbitMQ   │              │
  │       │◄──────────┘    └──────────────────►  │
  │       │    (stock)   (order.created event)   │
  ▼       ▼          ▼           ▼              ▼
MySQL   MySQL      MySQL       MySQL          MySQL
auth    inventory  orders      customers      finance
```

### Inter-Service Communication

| Type             | Services                    | Method           |
|------------------|-----------------------------|------------------|
| **Synchronous**  | Order → Inventory           | REST HTTP (Guzzle) |
| **Asynchronous** | Order → Finance             | RabbitMQ (AMQP)  |
| **Auth check**   | All services → Auth Service | REST HTTP        |

## Services

| Service          | Port | Database      | Description                              |
|------------------|------|---------------|------------------------------------------|
| api-gateway      | 8000 | —             | Routes all requests; validates JWT       |
| auth-service     | 8001 | auth_db       | Register, login, JWT issuance            |
| inventory-service| 8002 | inventory_db  | Books catalog & stock management         |
| order-service    | 8003 | orders_db     | Order lifecycle; calls Inventory + Finance |
| customer-service | 8004 | customers_db  | CRM — customer profiles                  |
| finance-service  | 8005 | finance_db    | Invoices; consumes RabbitMQ events       |

---

## Tech Stack

- **Framework**: Laravel 10.x (PHP 8.2)
- **Auth**: tymon/jwt-auth (JWT)
- **Message Broker**: RabbitMQ via php-amqplib
- **HTTP Client**: Guzzle (built into Laravel Http facade)
- **Database**: MySQL 8.0 (one per service)
- **Containerization**: Docker + Docker Compose
- **API Version**: `/api/v1/`

## Quick Start

### Prerequisites
- PHP 8.2+, Composer 2, Docker Desktop

### 1. Scaffold the project
```bash
chmod +x setup.sh
./setup.sh
```

### 2. Start all services
```bash
docker compose up --build -d
```

### 3. Generate APP_KEYs and JWT secret
```bash
# These are auto-generated by setup.sh, but if running manually:
docker exec bookstore-erp-api-gateway-1      php artisan key:generate
docker exec bookstore-erp-auth-service-1     php artisan key:generate
docker exec bookstore-erp-auth-service-1     php artisan jwt:secret
# Repeat for other services...
```

### 4. Verify
```
API Gateway:   http://localhost:8000/api/v1/
RabbitMQ UI:   http://localhost:15672  (guest / guest)
```

## Example: Place an Order (full flow)

```bash
# 1. Login
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@pagecraft.ph","password":"secret"}'
# → { "token": "eyJ..." }

# 2. Place order (Gateway → Order Service → Inventory Service → RabbitMQ → Finance)
curl -X POST http://localhost:8000/api/v1/orders \
  -H "Authorization: Bearer eyJ..." \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": 1,
    "customer_name": "Maria Santos",
    "shipping_address": "123 Colon St, Cebu City",
    "payment_method": "gcash",
    "items": [
      { "book_id": 1, "quantity": 2 },
      { "book_id": 4, "quantity": 1 }
    ]
  }'
```

**What happens behind the scenes:**
1. Gateway validates JWT → Auth Service
2. Gateway forwards to Order Service
3. Order Service calls Inventory Service (REST) → stock check
4. Order created in `orders_db`
5. Order Service calls Inventory Service (REST) → stock deducted
6. Order Service publishes `order.created` → RabbitMQ
7. Finance Consumer picks up event → Invoice created in `finance_db`

## Key Design Decisions

| Requirement | Solution | Justification |
|---|---|---|
| API Gateway | Laravel proxy controller | Single entry point; centralised auth |
| JWT Auth | tymon/jwt-auth | Laravel-native; stateless |
| Sync communication | REST / Guzzle HTTP | Needed for real-time stock check before order |
| Async communication | RabbitMQ | Invoice creation doesn't block order placement |
| No shared databases | One MySQL per service | Strict microservice isolation |
| Soft deletes | Eloquent SoftDeletes | Data integrity; auditability |
